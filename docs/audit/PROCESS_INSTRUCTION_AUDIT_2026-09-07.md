# Process Instruction Audit — 2026-09-07

Прямое поручение владельца: сократить расход токенов на проверку, сохранив адресный контроль для Codex и ChatGPT. Основной источник политики — раздел 5 [`RENPY_MCP_WORKFLOW.md`](../RENPY_MCP_WORKFLOW.md); маршруты исполнителей — [`DEVELOPMENT_WORKFLOW.md`](../DEVELOPMENT_WORKFLOW.md).

## Изменение и Change Impact

- `AGENTS.md`, оба workflow-регламента и TASK/Context Manifest templates направляют к проверкам по измененной области, краткому выводу и остановке после достаточного результата.
- PowerShell runner принимает suites/testcases, поддерживает lint-only и подробный диагностический режим, сохраняет полные логи и отдельные каталоги кадров без удаления старых.
- Завершение тестового процесса перенесено из `nastya_runtime` в общий `testsuite global` в `game/tests/runtime_regression_tests.rpy`: отдельные suites/testcases теперь штатно завершают игру. Runtime-имена testcase используют `::`; в каталогах Windows двоеточия заменяются дефисами. При traceback, timeout, ненулевом exit code или отсутствии выполненных успешных testcases runner не сообщает успех.
- GitHub workflow дает ChatGPT те же параметры через ручной запуск и краткий job summary; сохраняет артефакты для адресного разбора и просмотра UI. Автоматический push остается базовой smoke-проверкой, а не доказательством полного покрытия TASK.
- README, MASTER_SPEC, tasks/README и REPOSITORY_MAP уже ведут к основным регламентам; роли, навигация, жизненный цикл TASK и игровой канон не меняются. Board/Roadmap не требуют нового игрового статуса.
- Внешние Project Instructions текущего проекта ChatGPT из этого сеанса не прочитаны и не изменены. Проверка их актуальности остается внешним ограничением; известное расхождение не утверждается без доступа. Предыдущий audit от 2026-09-05 сохраняется как исторический результат.

Без доступа к runtime/кадрам выполнять доступные статические проверки и указывать конкретный непроверенный сценарий (`REMOTE_LIMITED`). Не повторять успешные проверки неизменившегося кода и не считать skipped CI или непросмотренные кадры успешной runtime/визуальной проверкой.

Это дополнение не заменяет остальные Project Instructions и не меняет творческие правила проекта.

### Дополнение после решения владельца об обязательной Git-синхронизации

> После принятия владельцем работы или перевода TASK в `done` завершать commit/push либо PR/merge и обновление канонической локальной `main`. Принятие разрешает эти действия без повторного подтверждения. Подтверждать общий SHA локальной `main` и GitHub `main`; ожидающий/skipped job или offline runner не являются синхронизацией. Перед следующей реализацией проверять этот факт: при расхождении сразу сообщить `SYNC PENDING`, сначала разрешить Git-синхронизацию, затем начинать следующую задачу. Подробности и безопасные ограничения — в `docs/DEVELOPMENT_WORKFLOW.md`, раздел «Обязательная синхронизация после принятия и перед следующей задачей».

Причины выявленного расхождения: локальные неопубликованные коммиты и рабочая ветка, новые удаленные коммиты, offline runner, блокировка безопасного sync неотслеживаемыми тестовыми артефактами. `Local safe sync` ранее исключал runtime-пути. Исправлены общие правила, TASK report template и workflow; добавлена команда `tools/check_git_sync.ps1`, тестовые снимки и Python cache исключены из Git без удаления файлов. Sync теперь охватывает все push и не требует Ren'Py SDK. При живой проверке обнаружено, что общий concurrency group отменяет ожидающий runtime-job; для sync и verify выделены отдельные группы, а последовательный доступ обеспечивает единственный runner `nastya-story`. Внешние Project Instructions по-прежнему недоступны для правки из этого сеанса.
