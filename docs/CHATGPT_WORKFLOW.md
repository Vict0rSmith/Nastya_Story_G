# Процесс работы ChatGPT с Nastya Story

Этот документ описывает основной маршрут работы через обычный ChatGPT-чат. Режим Work является резервным вариантом для задач, которым требуется длительный локальный цикл или недоступные чату инструменты.

## Вопрос о режиме выполнения

Перед существенной задачей ChatGPT может кратко спросить владельца:

> Реализовать задачу через обычный чат или через Work?

Ответ «чат» означает GitHub-маршрут: изменение файлов, commit/PR, запуск GitHub Actions и разбор summaries/artifacts. Ответ «Work» означает передачу задачи в отдельный длительный рабочий контур. Если вопрос не нужен по контексту или владелец его пропустил, используется обычный чат.

Это вопрос маршрутизации работы, а не игровое или репозиторное правило. Репозиторий не может сам изменить поведение интерфейса ChatGPT; для обязательного показа вопроса нужна отдельная настройка Project Instructions или поведения чата.

## Основной цикл через чат

1. Проверить репозиторий, ветку, SHA и отсутствие `SYNC PENDING`.
2. Выполнить изменение через GitHub в рамках прямого поручения или TASK.
3. Дождаться `Project health` и `Local safe sync` для опубликованного SHA.
4. При изменениях `game/`, runtime или UI запустить адресные suites/testcases через `tools/run_local_renpy_verify.ps1` (локально или вручную через workflow `Local Ren'Py verify`).
5. Прочитать краткий summary. Полные логи и изображения открывать только при ошибке или когда нужна визуальная проверка.
6. Для UI отдельно просмотреть нужные кадры из artifact. Успешный workflow без просмотра кадров не является визуальной проверкой.
7. В отчете указать SHA, выбранные проверки, artifacts, пропуски и уровень `FULL_LOCAL`/`REMOTE_LIMITED`.

## Уровни запуска

`smoke` запускает базовый `nastya_runtime`.

`targeted` запускает suites/testcases, переданные во входе `tests`, например `dialogue_layout,items_body_wardrobe`.

`lint-only` выполняет только lint и явно сообщает, что runtime не запускался.

`detailed` сохраняет расширенный диагностический лог. Это не заменяет просмотр кадров и не доказывает визуальное качество.

## Локальный контур

Перед расширенной Ren'Py-проверкой должен быть запущен интерактивный runner через `Nastya Sync START.cmd`. После окончания работы runner останавливается через `Nastya Sync STOP.cmd`. Если runner offline, локальная проверка считается недоступной, а не успешной.

## Обязательный итог

```text
SHA:
Project health:
Local safe sync:
Local Ren'Py verify:
Tests:
Artifacts:
Visual review:
Level: FULL_LOCAL / REMOTE_LIMITED
SYNC PENDING: yes / no
```
