# Карта мира — основной источник топологии

[`map.drawio`](map.drawio) — **единственный канонический источник карты Nastya Story**: состава пространств, их вложенности и существующих маршрутов между ними.

## Что принадлежит карте

`map.drawio` определяет:

- какие гиперкластеры, составные локации и помещения существуют на карте;
- какие пространства вложены друг в друга;
- между какими узлами существует маршрут;
- направление маршрута;
- системные точки маршрутизации, показанные отдельным типом узла.

Если карточка локации, старая документация или реализация расходится с `map.drawio` по этим вопросам, исправляется зависимый источник, а не карта, если владелец проекта прямо не утвердил новое изменение самой карты.

## Визуальная семантика схемы

Текущая условная нотация карты:

- **зеленый внешний контейнер** — гиперкластер / крупная зона мира;
- **зеленый обычный прямоугольник** — основной экран/точка входа крупной зоны;
- **красный контейнер** — составная локация или объект, внутри которого находятся отдельные игровые пространства;
- **синий обычный прямоугольник** — конкретное пространство/точка пребывания;
- **оранжевый ромб** — системная точка взаимодействия/маршрутизации, а не самостоятельная локация пребывания; в частности, автобусная остановка на карте представляет транспортный маршрутизатор;
- **двусторонняя стрелка** — маршрут существует в обе стороны;
- **односторонняя стрелка** — маршрут существует только в направлении стрелки;
- **линия без стрелок** используется для системной связи/маршрутизации и сама по себе не означает обычный переход игрока между двумя локациями.

Расположение блоков на полотне служит для читаемости. Каноническими являются сами узлы, их вложенность и связи, а не абсолютные координаты на экране.

## Как читать стрелки в raw XML draw.io

Это важно для ChatGPT, Codex, скриптов и любых других агентов, которые читают `map.drawio` как XML, а не глазами в diagrams.net.

В draw.io отсутствие свойства стрелки в `style` **не означает автоматически `none`**. Для обычного connector значение конца стрелки по умолчанию может применяться самим draw.io. Поэтому нельзя определять односторонность только по тому, что в XML явно записан один из параметров `startArrow` / `endArrow`.

Правило чтения:

- если в diagrams.net видны наконечники с двух сторон — маршрут двусторонний;
- если в XML задано `startArrow=classic`, а `endArrow` отсутствует, это **не основание** считать маршрут односторонним: draw.io может использовать стандартный `endArrow=classic`, и визуально линия будет двусторонней;
- отсутствие стрелки с конкретной стороны должно определяться по **явному** `startArrow=none` или `endArrow=none` либо по фактическому отображению в diagrams.net;
- пример настоящего одностороннего перехода: `startArrow=none;endArrow=classic` — переход только к `target`;
- `startArrow=classic;endArrow=classic` — явно двусторонняя линия;
- `startArrow=none;endArrow=none` — линия без стрелок; для карты это обычно системная связь, а не обычный переход игрока.

При споре между примитивным XML-парсером и тем, как стрелка реально отображается в diagrams.net, сначала проверить draw.io-defaults и явные `none`, а не объявлять линию односторонней по отсутствующему атрибуту.

## Машинные идентификаторы узлов

Каждый значимый узел карты должен иметь стабильный атрибут `mapNodeId`.

Текущая схема префиксов:

- `hc_*` — гиперкластер / крупная зона;
- `loc_*` — локация, составная локация или конкретное пространство;
- `route_*` — системная точка маршрутизации.

Примеры:

- `hc_residential_district`;
- `loc_apartment_5_hallway`;
- `loc_central_shopping_center_floor_1`;
- `route_bus_stop_residential`.

`mapNodeId` — **проектный стабильный ID**. Внутренний draw.io-атрибут `id` (`e047`, `xkRBR...` и т. п.) является служебным идентификатором XML и не должен использоваться в коде, карточках или других документах как ID сущности.

Видимая подпись (`label` / `value`) может быть человекочитаемой и меняться при уточнении названия. `mapNodeId` не переименовывается только ради косметики; его меняют только если действительно меняется сама сущность и это изменение утверждено владельцем.

## Доступность

Карта показывает **постоянную топологию мира**, а не доступность на конкретный день или этап прохождения. Наличие узла или стрелки не означает, что маршрут уже доступен игроку.

Текущая доступность задается карточкой локации и применимыми игровыми флагами/условиями. Для новых карточек используется стандарт из [`../templates/LOCATION_TEMPLATE.md`](../templates/LOCATION_TEMPLATE.md).

Временные пометки вроде «закрыто» не являются частью топологии и не должны использоваться как способ кодировать доступность на карте.

## Правило безопасной технической правки `map.drawio`

Если задача состоит только в добавлении/исправлении системных подписей (`mapNodeId`, человекочитаемый текст, не меняющий сущность), **не трогать топологию и геометрию**.

Без отдельного поручения запрещено одновременно с такой технической правкой:

- менять `source` или `target` у edge;
- менять `parent` узлов/стрелок;
- переподключать линии к другим узлам;
- удалять или создавать связи;
- менять направление стрелок;
- менять `<mxGeometry>`, координаты, размеры, waypoints и ручную трассировку линий;
- переименовывать служебные draw.io `id` без необходимости;
- оборачивать существующий `mxCell` в новую XML-структуру или разворачивать существующий `UserObject` только ради добавления `mapNodeId`;
- выполнять автоматическую «нормализацию» XML, которая может заставить diagrams.net пересоздать или перепривязать связи.

При добавлении `mapNodeId` к уже существующему `mxCell` предпочтительно добавить только сам атрибут в существующий элемент, оставив остальные атрибуты и дочерний `mxGeometry` без изменений.

После любой программной правки карты минимум проверить diff: если поручение было только про метаданные, в diff не должны неожиданно меняться `source`, `target`, `parent` или `mxGeometry`.

## Ошибки и сомнения в карте

Если агент замечает возможную ошибку топологии, дублирующую связь, странное направление стрелки или опечатку, но владелец не поручал исправлять это место, агент должен **сообщить о находке и не менять ее самовольно**.

Особенно нельзя «чинить» направление перехода только потому, что raw XML был неверно интерпретирован без учета draw.io-defaults.

## Другие графы

Старые Mermaid-файлы `residential_district.mmd` и `residential_navigation.mmd` удалены как устаревшие конкурирующие представления. Новые отдельные графы не создаются для дублирования `map.drawio`.

Карточки локаций хранят смысл, визуальный паспорт, объекты, действия, NPC и условия доступа, но не становятся вторым владельцем топологии.

Change-impact: [`../REPOSITORY_MAP.md`](../REPOSITORY_MAP.md).


## Синхронизация с игрой

`tools/sync_world_map.py` компилирует карту и поля доступа карточек в `game/content/world_map.rpy`, а также обновляет параметризованные визуальные тесты всех мест пребывания. Сгенерированные файлы не редактируются вручную. Проверка актуальности: `python tools/sync_world_map.py --check`; она также включена в `tools/project_health_check.py`.

В runtime отдельно хранятся помещения, контейнеры и маршрутизаторы. `loc_masha_school` сохранен в реестре ради существующего расписания Маши; игрок не может перемещаться в контейнер вместо конкретного помещения. Повторные линии не создают повторные кнопки. Для системных линий без наконечников строятся транспортные связи; направление линий со стрелками сохраняется.
