# Nastya Story — план реализации и статус готовности

Статус документа: **живой сводный план реализации**.

Последняя проверка: **2026-09-06**.
Обновление статуса TASK-008 после приемки владельцем: **2026-09-08** (без повторного аудита остальных систем).

## 1. Назначение

Этот файл нужен как единая точка ответа на вопросы:

- что в игре уже реализовано;
- что реализовано частично;
- что спроектировано, но еще не реализовано;
- что осталось доделать;
- какие крупные направления еще не начаты;
- какие реализации уже переданы на проверку владельцу.

Этот документ **не является вторым источником канона механик, мира или интерфейса**. Подробные требования всегда берутся из соответствующих `docs/systems/`, `docs/world/`, `docs/content/` и утвержденных TASK. Здесь хранится только краткий статус реализации и ссылка на основной источник требования.

При расхождении этого плана с канонической спецификацией приоритет имеет спецификация. При расхождении с фактическим кодом статус в этом плане должен быть обновлен после проверки реализации.

## 2. Статусы

Используются только следующие признаки:

- **DONE** — требование реализовано и принято либо фактически завершено без известных незакрытых пунктов.
- **REVIEW** — реализация выполнена и находится на проверке владельца; может потребовать корректировки.
- **PARTIAL** — часть системы работает, но существенная часть требований еще отсутствует.
- **NOT_STARTED** — каноническое требование существует, но рабочей реализации по существу нет.
- **TBD** — само проектное решение еще не определено полностью; реализация не должна угадывать недостающие параметры.

После завершения любого TASK или заметной ручной правки необходимо проверить, затронуты ли строки этого плана, и обновить:

1. статус;
2. блок «Сделано»;
3. блок «Осталось»;
4. ссылку на TASK/implementation report при наличии;
5. дату последней проверки документа.

## 3. Текущий приоритет разработки

Главная ближайшая цель — сделать **29 августа полноценным первым управляемым игровым днем**, в котором игрок может выйти из квартиры, перемещаться по району и в университет, выполнить обязательные цели дня, пользоваться базовой экономикой и интерфейсами без прототипных заглушек.

Рекомендуемый порядок:

1. карта доступных локаций и переходы первого дня;
2. транспорт между гиперкластерами;
3. обязательные действия квеста 29 августа;
4. магазин и базовая покупка предметов/еды;
5. питание, голод и временные эффекты HUD;
6. телефон первого дня и университетское приложение;
7. карточка Маши и исправление карточки Насти;
8. унификация UI и замена графических/текстовых заглушек;
9. ситуативные события первого дня;
10. затем — полноценный университетский цикл с 1 сентября.

# 15. Правило сопровождения этого плана

Этот файл должен обновляться **при каждом принятом заметном изменении реализации**.

Минимальная процедура после завершения работы:

1. прочитать implementation report или проверить изменение в коде;
2. найти соответствующую строку в этом плане;
3. изменить статус;
4. кратко дописать реально сделанное;
5. удалить из «Осталось» то, что действительно закрыто;
6. не отмечать `DONE`, если остается существенная пользовательская часть системы;
7. обновить дату последней проверки.

Если реализована только техническая основа без доступной игроку функции, статус обычно остается **PARTIAL**, а не `DONE`.
