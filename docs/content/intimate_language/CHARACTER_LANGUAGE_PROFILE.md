# Character Language Profile — привязка общего словаря к голосу персонажа

## 1. Владелец индивидуальной речи

Этот файл задает формат профиля, но не хранит предпочтения конкретных персонажей.

Устойчивые слова, частота, грубость, уменьшительность, мат, социальный фильтр и запреты конкретного персонажа принадлежат его world/characters/*_canon.md.

## 2. Статусы формы

Для term/action form:

- PREFERRED — естественный основной вариант;
- ALLOWED — нормально возможный;
- SITUATIONAL — только в определенном состоянии/отношениях;
- RARE — возможен, но не характерен;
- AVOIDED — обычно персонаж так не говорит;
- FORBIDDEN — закрепленно не использовать без изменения канона;
- TBD — не определено.

### Дефолт при TBD

`TBD` индивидуальной лексики означает отсутствие утвержденных **персонажных предпочтений**, а не отсутствие естественной речи.

Пока профиль не определен:
- персонаж говорит на обычном современном разговорном русском по общим правилам `DIALOGUE_WRITING_GUIDE.md`;
- не выбирать анатомический/медицинский термин только потому, что он точнее совпадает с внутренним BODY ID;
- не придумывать персонажу устойчивое любимое разговорное, ласкательное, грубое или обсценное слово;
- выбирать немаркированную разговорную формулировку по контексту или обходиться описанием действия/пространства, если точное существительное человеку обычно не понадобилось бы;
- `ANAT`/technical wording применять только при медицинской, научной, формальной или иной реально требующей точности ситуации либо после отдельного закрепления такого регистра за персонажем.

Таким образом, `TBD` сохраняет индивидуальный голос неопределенным, но **не делает речь медицинской, книжной или стерильно нейтральной**.

## 3. Контекстные оси

Отношение к телу:
- SELF_BODY;
- PARTNER_BODY;
- FRIEND_BODY;
- STRANGER_BODY.

Ситуация:
- PRIVATE;
- CASUAL;
- INTIMATE;
- SEXUAL;
- MEDICAL;
- FORMAL.

Эмоция/режим:
- JOKING;
- ANGRY;
- EMBARRASSED;
- AROUSED;
- SHOCKED;
- PAIN;
- TIRED.

Один термин может менять статус в разных контекстах.

## 4. Формат раздела canon-карточки

Рекомендуемая структура под заголовком «Индивидуальная лексика»:

- общая манера телесной/интимной речи;
- устойчивые PREFERRED-маркеры;
- SITUATIONAL/RARE формы;
- допустимый уровень мата/грубости;
- контекстные переключения (медицинский, формальный, сексуальный, шутливый и т. п.);
- явные AVOIDED/FORBIDDEN, только если они действительно утверждены;
- ссылка на этот раздел и общий Intimate Language System.

Не нужно перечислять весь общий словарь.

## 5. Разделение авторской речи и речи персонажа

AUTHOR/NARRATOR (этот пункт — единственный владелец правила о регистре названий частей тела в авторской речи; остальные документы ссылаются сюда):
- при близком POV персонажа (основной режим игры) дефолт авторской речи для частей тела — разговорный default проекта (`COLL`/`AFF`), ориентированный на телесный словарь POV-персонажа из его canon-карточки (для Насти: писечка, попка, сисечки, сосочки и т. п.);
- `ANAT`-формы в авторской речи — только в медицинском, учебном или формальном контексте сцены либо если без термина теряется физический факт;
- автор не обязан копировать любимое слово персонажа дословно, но выбирает форму того же регистра;
- часть тела в фокусе действия называется, а не заменяется пространственным описанием — [`INTIMATE_LANGUAGE_SYSTEM.md`](INTIMATE_LANGUAGE_SYSTEM.md) §4.

CHARACTER SPEECH / INNER SPEECH:
- использует индивидуальный профиль;
- может переключать регистр по ситуации;
- не получает термин только потому, что он есть в BODY_LEXICON.

## 6. Пример абстрактного профиля

Пример не относится к реальному персонажу проекта:

- body.vulva / SELF_PRIVATE → PREFERRED: мягкое разговорное;
- body.vulva / MEDICAL → ALLOWED: анатомическое;
- body.breast / JOKING → SITUATIONAL: разговорное;
- action.masturbation / CASUAL → AVOIDED;
- OBSC vocabulary / ANGRY → SITUATIONAL.

Конкретные слова должны находиться в canon-карточке.

## 7. Новые устойчивые маркеры

Если в сцене получилась удачная новая фраза:
1. она может остаться разовой ситуативной репликой;
2. она не становится постоянным речевым маркером автоматически;
3. для повторного системного использования ее отдельно утвердить и внести в canon-карточку персонажа.

Это сохраняет правило «один факт — один основной источник».
