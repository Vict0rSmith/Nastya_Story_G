# TASK-001 — Создать полноцветные кнопки HUD с изображениями и подключить их в интерфейс

## Цель

Заменить текстовые, однотонные или временные кнопки HUD на полноценные визуальные кнопки с цветными изображениями, чтобы HUD выглядел как игровой интерфейс, а не как технический прототип.

## Основание

HUD уже описан в актуальной UI-спецификации проекта. Codex не должен придумывать состав HUD, список кнопок или их назначение по памяти — нужно взять их из `docs/systems/UI_VISUAL_SYSTEM_SPEC.md` и реализовать визуальную часть в соответствии с этой спецификацией.

## Что реализовать

1. Прочитать `docs/systems/UI_VISUAL_SYSTEM_SPEC.md` и определить:
   - какие именно элементы HUD являются кнопками;
   - какие из них уже существуют в коде;
   - какие сейчас используют текст, заглушки, простые прямоугольники или иные временные решения.
2. Для каждой кнопки HUD, предусмотренной спецификацией, создать полноценный визуальный ассет:
   - полноцветная кнопка;
   - понятное тематическое изображение / иконка по смыслу кнопки;
   - единый визуальный стиль для всего набора;
   - читаемость на реальном HUD-размере.
3. Для каждой кнопки подготовить необходимые состояния, если они поддерживаются текущим UI:
   - normal / idle;
   - hover;
   - selected / active, если применимо;
   - insensitive / disabled, если применимо.
4. Подключить новые кнопки в интерфейс игры:
   - заменить существующие временные визуальные решения;
   - сохранить текущую логику нажатий и поведения;
   - не ломать расположение HUD, если это не требуется реализацией.
5. Разместить ассеты в логичной структуре UI-ресурсов проекта и подключить их через код/экраны Ren’Py.

## Данные и сущности

Codex должен сам взять точный перечень кнопок HUD из `docs/systems/UI_VISUAL_SYSTEM_SPEC.md`.

Если в коде уже есть соответствующие экранные элементы, нужно сопоставить их со спецификацией и заменить только визуальную часть.

## UI / UX

- Кнопки должны быть полноцветными, а не текстовыми заглушками.
- Кнопки должны быть визуально различимыми и понятными по смыслу.
- Набор должен выглядеть целостно: единая стилистика, форма, контур, фон, читаемость.
- Кнопка должна оставаться понятной без необходимости читать длинную текстовую подпись.
- Если в текущем интерфейсе есть текстовые подписи или tooltip, не удалять их без необходимости; задача в первую очередь про визуальные кнопки.

## Контент

- Для каждой кнопки требуется собственное тематическое изображение/иконка.
- Изображения не должны быть случайным набором разнотипных пиктограмм.
- Визуальный стиль должен ощущаться как часть одной HUD-системы.

## Интеграции с существующими системами

Проверить совместимость с:
- существующими экранами HUD;
- текущими действиями и переходами, привязанными к кнопкам;
- общей UI-структурой проекта.

Если кнопка взаимодействует с системным состоянием игры, менять только визуальную часть, а не ее механику.

## Не делать

- Не придумывать новые HUD-кнопки, если их нет в спецификации.
- Не менять состав HUD по собственной инициативе.
- Не менять игровую механику кнопок.
- Не перерабатывать весь HUD целиком, если задача требует только заменить кнопки.
- Не проводить несвязанный рефакторинг UI «заодно».
- Не менять канон и не редактировать проектные спецификации ради удобства реализации.
- Не подменять полноцветные кнопки временными текстовыми или одноцветными заглушками.

## Критерии приемки

Задача считается выполненной, если:

1. Все HUD-кнопки, предусмотренные `docs/systems/UI_VISUAL_SYSTEM_SPEC.md`, получили полноценные визуальные ассеты.
2. Ассеты подключены в интерфейс игры.
3. В игре HUD отображает именно цветные кнопки с изображениями, а не текстовые/технические заглушки.
4. Состояния кнопок (hover / active / disabled), если они поддерживаются текущей реализацией, визуально различимы.
5. Интерфейс не ломается и не выдает ошибок.
6. Поведение самих кнопок осталось прежним, если иное прямо не требовалось.
7. Структура файлов UI-ассетов в проекте осталась логичной и понятной.

## Зависимости

- Актуальная `docs/systems/UI_VISUAL_SYSTEM_SPEC.md`.
- Текущая реализация HUD в коде/экранах Ren’Py.
- Актуальные правила работы Codex из `AGENTS.md`.

## Требуемые проверки

- Проверить, что все кнопки видны в HUD.
- Проверить, что кнопки вызывают те же действия, что и раньше.
- Проверить, что новые изображения реально подключены, а не лежат неиспользуемыми файлами.
- Проверить, что hover/active/disabled состояния корректно отображаются, если они предусмотрены реализацией.
- Проверить отсутствие ошибок интерфейса при запуске соответствующих экранов.

## Примечания для Codex

Перед изменениями прочитать:
- `AGENTS.md`;
- `docs/systems/UI_VISUAL_SYSTEM_SPEC.md`;
- конкретные UI-файлы и экранные реализации, которые относятся к HUD.

Если UI-спецификация не определяет какой-то мелкий визуальный нюанс, можно принять минимальное локальное решение, не меняющее дизайн системы в целом.

Если в ходе работы выяснится, что для нормальной реализации требуется новое дизайнерское решение уровня спецификации, остановиться и кратко зафиксировать блокер, а не придумывать новый дизайн самостоятельно.
