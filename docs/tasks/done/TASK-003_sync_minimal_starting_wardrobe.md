# TASK-003 — Синхронизация стартового гардероба с актуальным каноном

## Цель

Привести фактическую реализацию стартового гардероба Насти в Ren'Py к актуальному канону после перехода на минимальный стартовый набор и удалить из активной реализации старые стартовые вещи, которые больше не входят в канон.

## Основание

Актуальный канон Насти устанавливает:

- два комплекта простого белого хлопкового белья: трусики + лифчик;
- повседневную одежду: футболка + юбка;
- обувь: кроссовки;
- отдельный комплект одежды для института, состав которого пока `TBD` и потому не должен заполняться реализацией самостоятельно.

Системная спецификация гардероба допускает намеренно минимальный стартовый набор и не требует нескольких альтернативных повседневных комплектов. Конкретный состав стартового гардероба берется только из карточки персонажа.

На момент постановки задачи в реализации обнаружены устаревшие стартовые вещи:

- `game/content/definitions.rpy`: `blue_dress`, `jeans`, `coral_top`;
- `game/domain/core.rpy`: эти же предметы добавляются в `wardrobe.owned`, а `blue_dress` используется как стартовая надетая одежда.

## Что реализовать

1. Перед изменениями проверить текущую реализацию гардероба, экраны и все места инициализации новой игры.
2. Удалить из стартового набора Насти `blue_dress`, `jeans`, `coral_top` и любые другие вещи, отсутствующие в актуальном каноне.
3. Зарегистрировать и использовать стартовые канонические вещи Насти: два белых комплекта белья, футболку, юбку и кроссовки.
4. Стартовый надетый комплект на утро 29 августа должен соответствовать каноническому сценарию: белое белье, футболка; остальные надетые элементы определить только из уже утвержденного канона/сценария и существующей логики, не придумывая новых вещей.
5. Если для двух одинаковых белых комплектов системе нужны разные стабильные item ID, выбрать технически устойчивую схему идентификаторов без изменения визуального или сюжетного смысла и явно указать ее в implementation report. Не превращать технические ID в новый дизайнерский факт.
6. Поддержать обувь в стартовом наборе только в той степени, в которой текущая архитектура уже позволяет это сделать. Если слот `shoes` существует, кроссовки должны быть зарегистрированы и принадлежать Насте; не вводить отдельную новую механику обуви сверх текущей спецификации.
7. Не создавать предметы институтского комплекта: его состав остается `TBD`. При необходимости обеспечить только совместимость архитектуры с будущим учебным контекстом.
8. Проверить гардеробный UI и логику новой игры на отсутствие ссылок на удаленные старые вещи.
9. Почистить неиспользуемые определения старого стартового гардероба, если после синхронизации на них нет других действующих ссылок.

## Данные и сущности

Основной источник конкретного состава: `docs/world/characters/nastya_canon.md`.

Системные правила: `docs/systems/RELATIONSHIPS_INVENTORY_WARDROBE_SPEC.md`.

Не создавать второй список канона в коде сверх необходимых игровых definitions/data: код является реализацией утвержденного состава, а не новым источником дизайна.

## UI / UX

- Гардероб не должен показывать старые стартовые вещи, удаленные из канона.
- Минимальный стартовый набор не должен искусственно дополняться ради заполнения сетки или получения нескольких вариантов одежды.
- Элементы с `TBD` не показывать как существующие вещи до их утверждения.

## Контент

Литературный пролог и каркас 29 августа уже синхронизированы на уровне `docs/`. Не переписывать сюжетный текст в рамках этой задачи.

## Интеграции с существующими системами

- сохранить единый `WardrobeState` и существующие технические слоты;
- не вводить дублирующие флаги вида `is_wearing_*`;
- проверить создание новой игры, открытие гардероба, надевание/снятие вещей и сохранение/загрузку в рамках текущей схемы;
- если изменение набора требует миграции schema/save, выполнить ее минимально и описать в отчете; не повышать schema version без реальной необходимости.

## Не делать

- Не придумывать цвет, фасон, длину или другие визуальные параметры футболки, юбки и кроссовок.
- Не создавать одежду для института до утверждения ее состава.
- Не добавлять второй повседневный комплект ради разнообразия.
- Не менять канонические файлы `docs/world/`, `docs/systems/` или `docs/content/` ради удобства реализации.
- Не расширять механику гардероба за пределы требований этой задачи.
- Не менять гардероб Маши: в текущем игровом коде задача касается реализации гардероба управляемой Насти; если обнаружится отдельная фактическая реализация Машиного гардероба со старой футболкой, включить только удаление этого явного противоречия и описать его в отчете.

## Критерии приемки

- В новой игре Настя владеет только утвержденными стартовыми вещами и не получает `blue_dress`, `jeans`, `coral_top` как стартовые предметы.
- Реализация содержит два белых комплекта белья, футболку, юбку и кроссовки согласно канону.
- Стартовое состояние одежды 29 августа не противоречит `2026-08-29_DAY_OUTLINE.md`.
- Институтская одежда не выдумана и остается `TBD` на уровне конкретных предметов.
- Старые неиспользуемые определения и ссылки очищены.
- Гардероб открывается и базовые операции с вещами работают без ошибок.
- Новая игра запускается без ошибок и не содержит ссылок на удаленные item ID.
- Существующие сохранения либо продолжают корректно загружаться, либо изменение схемы/миграция явно реализованы и описаны.

## Зависимости

Нет внешних проектных решений, необходимых до начала реализации. Конкретный институтский комплект намеренно остается вне задачи до отдельного утверждения.

6. Проверка отсутствия самостоятельно созданных предметов институтской одежды.
