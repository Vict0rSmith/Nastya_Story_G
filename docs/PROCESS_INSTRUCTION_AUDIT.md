# Process Instruction Audit — контроль актуальности рабочих инструкций

## Назначение

Этот документ задает обязательную мета-проверку при существенном изменении принципов, механизмов или инфраструктуры работы над Nastya Story.

Он не является источником игрового канона и не задает конкретные игровые механики.

## Когда проверка обязательна

Проверка выполняется, если меняется хотя бы один из элементов:

- порядок работы ChatGPT и Codex;
- жизненный цикл TASK;
- правила загрузки контекста;
- Context Manifest;
- Development Board / Roadmap;
- GitHub workflow, PR-процесс или автоматические проверки;
- локальная синхронизация;
- Ren'Py MCP-контур;
- распределение ролей между владельцем, ChatGPT, Codex и автоматизацией;
- принцип определения источника истины или навигации по базе знаний.

## Что необходимо сверить

После такого изменения исполнитель (Grok Bot, ChatGPT, Codex или другой) обязан отдельно проверить доступные слои:

1. **Project Instructions текущего проекта ChatGPT** — соответствуют ли они новому принятому порядку работы и не содержат ли устаревших или конфликтующих правил.
2. **Инструкции Codex** — прежде всего корневой `AGENTS.md` и другие применимые инструкции, которые Codex обязан читать.
3. **`docs/DEVELOPMENT_WORKFLOW.md`** — отражает ли он фактически принятый рабочий процесс.
4. **`docs/MASTER_SPEC.md`, `README.md`, `docs/tasks/README.md` и связанные MOC** — если изменение затронуло их навигационную или процессную роль.

## Результат проверки

Если найдено расхождение:

- доступные репозиторные инструкции обновляются в рамках той же правки либо отдельного явно связанного изменения;
- если внешний слой инструкций нельзя изменить из текущего инструмента (например, Project Instructions ChatGPT), ChatGPT обязан прямо сообщить владельцу, что именно устарело, и дать точную формулировку для обновления;
- нельзя считать новую схему работы полностью зафиксированной, если известное расхождение между рабочими инструкциями просто проигнорировано.

Если внешние Project Instructions недоступны для чтения, не объявлять их проверенными или устаревшими по предположению. Зафиксировать ограничение и дать короткое дополнение со ссылкой на репозиторный источник; остальные доступные изменения завершить. Пример актуального дополнения после оптимизации проверок: [`audit/PROCESS_INSTRUCTION_AUDIT_2026-09-07.md`](audit/PROCESS_INSTRUCTION_AUDIT_2026-09-07.md).

Если расхождений нет, отдельный отчет не обязателен; достаточно фактически выполнить сверку.

## Граница ответственности

Эта проверка касается только мета-правил разработки и доступа к знаниям. Она не превращает Project Instructions, `AGENTS.md` или этот документ в источник канона персонажей, мира, механик, сюжета или контента.
